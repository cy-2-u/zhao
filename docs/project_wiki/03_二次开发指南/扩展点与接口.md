# 扩展点与接口（0.6.1）

## 环境与协议

- Node.js ≥ 18，零第三方依赖，ES Modules。
- `AUTO_REVIEW_DATA_DIR` 重定向运行时数据目录，用于隔离测试。
- 标准 hook 输出在 `src/decision.js`，仅使用 hookSpecificOutput；不再使用 simple 输出开关或插件对话框环境变量。
- PreToolUse 与 PermissionRequest 均注册在 `hooks/hooks.json`，预算各 120000ms；修改注册后核实客户端加载状态。PreToolUse 使用 `permissionDecision/permissionDecisionReason`，PermissionRequest 使用 `decision.behavior/message`，两套字段不可混用。PermissionRequest 的决策输出以客户端实际接受为准，不接受或不触发该事件时安全退化为原生弹窗。
- `provider_retries` 的配置范围仍为 0～3，但 `src/provider.js` 会按 120 秒 hook 总预算和收尾余量动态收紧实际重试次数；扩展文档不得按固定 `4 × timeout` 推算等待时间。

## 扩展审查工具

1. 扩展 hook matcher 以接收对应工具。
2. 在 reviewer 中补充工具别名、输入结构校验、完整审查对象构造。
3. 纳入 review_tools，并测试不接管、合法输入、缺失字段与超限等情况。
4. 不得仅把工具名加进范围就假定已有安全覆盖，尤其要检查路径和附件边界。

## 规则与快速通道

config 中出厂配置是回落源，用户数据目录配置优先。添加规则须复用 CLI/加载端校验，不另造放宽上限的入口。保持 `ask > deny（提示）> allow`，ask 按 `ask_policy` 分流（model 降级送审 / user 转用户）且仅在接管管线内生效；规则表超限不能截断后误放行。

快速通道是保守命令参数校验，不是命令名称白名单。组合命令按段判定：cd 段单独放行，其余段须过严格双门禁；段尾纯 stderr 重定向（`2>&1`/`2>nul`/`2>/dev/null`）先剥离。新增 Git 选项或 shell 形式时逐项检查副作用、外部程序调用与配置注入可能性。无法可靠识别时退出捷径，不承诺通用 shell 解析。

用户 allow 规则的信任边界是用户正则；`userAllowSegmentSafe` 只兜底确定性逃逸形态（命令替换、反引号、引号外重定向、未闭合引号、`\&` 类跨 shell 歧义、`%VAR%` 展开），不要移除这些兜底来"放宽"白名单。

`rules test` 只匹配已保存规则，不执行命令、不测试未保存 pattern、不模拟完整模型管线。

## 载荷与附件

新增字段必须先按原始结构脱敏再序列化，工具与附件共享 max_payload_chars 单一预算，计入上下文、提示和格式开销。字段超限或缺少必要内容时 ask，不以裁掉危险后半段换取模型 allow。

附件检查按路径组件覆盖敏感目录，并检查 cwd 边界、链接与普通文件属性。truncated 脚本不得自动 allow。不要将脱敏描述成覆盖所有 secret，也不要将上下文隔离描述成注入免疫。

## 模型契约与渠道

保持模型 `decision/risk_level/analysis/risks/scope/alternative` 字段契约；模型只能输出 allow/deny，模型 ask 收敛 deny。provider 瞬时故障按 `provider_retries`（0~3）配置重试，实际次数受 120 秒 hook 总预算约束；重试后仍失败与解析失败 ask。渠道四项 base_url、api_key、api_kind、model 保持不变，审批只认专用渠道。渠道展示和错误信息需保护短 key。

扩展其他客户端应单独适配输出 schema，不恢复已移除的 simple 或 GUI 接口。

## 缓存与写入

缓存键需要覆盖策略（含 ask_policy）、工具输入、cwd 与附件摘要；读取严格检查 schema、有限 expires、未过期及合法模型决策。不要无条件兼容旧键、无期限条目或把人工授权混入模型结论缓存。pending 标记只承载 15 秒短时效的"第一层刚转人工"凭证，不要把它当跨会话授权存储；命中、未命中、error 三态必须分开，损坏或锁/读写故障按 error 退避人工。配置/规则写入失败必须让 CLI exit 1，不先输出成功。

## 验证

在项目根目录运行 `npm test`。使用隔离数据目录与本地模拟审批渠道覆盖规则优先级、危险参数、完整性门槛、总预算、敏感路径、短 key、无效缓存、pending error 和写失败场景；单独验证 PreToolUse 与 PermissionRequest 的双协议。不要实际执行危险命令做验收，不硬编码测试计数。`provider test` 真实联网，须与离线回归分开。真实客户端是否把内置子智能体请求送入 PermissionRequest 仍需实机验证，不能用脚本级测试替代。
