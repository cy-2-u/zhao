# 常见问题（0.6.1）

## GUI、审查窗口与 session 命令去哪里了？

当前版本已移除插件 GUI、自建审查对话框与插件会话白名单。不要使用旧版 `gui`、`session`、`dialog_on_ask`、`ask_to_user` 配置方式；触达用户的请求统一交客户端原生审批，会话内允许由客户端自行处理。远程端能否呈现审批由客户端决定，插件不根据不可信来源字符串猜测远程状态。

## 为什么开了插件仍然询问？

默认 `ask_policy=model` 下，插件接管的请求只在以下情形弹给你：审批模型未配置或重试后仍故障、超出 payload 预算、必要审查内容不完整、pending 标记无法可靠读取/消费，以及 `ask_policy=user` 时命中的 ask 门槛。若客户端没有触发相应 hook、工具范围外或处于非接管模式，也会走客户端原生流程。先检查 `/auto-review`、自动编辑权限模式及 hook 日志。

## 关机命令怎么不再弹窗了？

默认 `ask_policy=model` 把你设置的 ask 确认门槛（如出厂关机规则）降级为送审风险提示，由审批模型结合完整命令终审。真实关机/重启按默认提示词通常 deny，`shutdown /a` 等取消动作可以 allow；模型裁决 allow 时不再打扰你，模型不可用时才转人工。想要“这类命令必须弹窗给我点头”，执行 `/auto-review set ask_policy user` 恢复恒转用户确认。

## 子智能体的命令还弹窗吗？

这取决于客户端是否把该调用交给父级 PermissionRequest hook。插件的 `hook_permission.js` 已验证能对实际收到的请求输出 allow/deny（`decision.behavior/message`），其余情况空输出退回原生弹窗；但脚本级测试不能证明每个客户端版本的内置子智能体都会触发这个 hook。若客户端完全绕过父级 hook runner，插件在不修改客户端的前提下无法强行接管，因此仍会弹原生审批框。

## ask 与 deny 谁优先？

固定为 `ask > deny（风险提示）> allow`，不取决于数组顺序。ask 只在管线接管后生效；deny 规则不是立即拒绝，而是禁止捷径并携带提示送审。模型 deny 才是模型层拒绝；模型返回 ask 按 deny 处理，故障兜底 ask 则保留人工确认。`model` 策略下 ask 门槛同样压过 allow（降级为送审提示），不会被宽泛 allow 遮蔽。

## rules test 能验证拟添加 pattern 吗？

不能。`/danger-rules test 'git status'` 测试的是已经保存的规则，不会执行这段命令，也不模拟完整审查管线。添加前审阅正则和范围，经授权保存后再 test；未命中不等于安全或自动放行。

## 为什么普通 Git 命令也没有快速放行？

快速通道不仅看命令名，还检查参数、路径和结构。危险或未知选项、包装器、重定向、命令替换或无法可靠解析的语法会退出捷径。不是所有 Git 参数安全，解析器也不是所有 shell 的完整实现。不要用宽泛 allow 消除这些检查。

## 脚本会发给谁？截断后是否仍会自动允许？

开启 inspect_scripts 后，允许附加的内容会发给 `review_provider.json` 中的专用渠道。只尝试读取 cwd 内普通文件，并检查越界、链接、敏感目录路径组件及文件类型。工具内容、附件、上下文、规则提示和格式开销共享单一总预算；必要输入缺失或脚本标记 truncated 时不能自动 allow，应转人工。默认关闭此功能，开启前确认渠道可信。

## 脱敏能保证所有秘密都不外泄吗？

不能。实现先脱敏原始字段再序列化，并保护渠道展示中的短 key，但只覆盖已识别的凭据模式。附件可能包含未识别的秘密。分享日志、截图或配置前仍须检查，不要依赖绝对“不会泄漏”的承诺。

## 审批渠道如何排查？

`provider path` 定位配置，保留 base_url、api_key、api_kind、model 四项；`provider show` 脱敏展示；`provider test` 真实联网检查。未配置、认证失败、超时或输出无效时，需要模型的请求转 ask，不回落客户端 provider。瞬时故障（超时/5xx/429）按 `provider_retries`（默认 2，配置范围 0～3）自动重试，但有效次数受 120 秒 hook 总预算限制；4xx 永久错误不重试。连通性测试不是 `npm test` 的一部分。

## 缓存是否固定一小时？旧缓存兼容吗？

不固定，TTL 取决于 cache_ttl_seconds，0 禁用。缓存只复用有效 schema、有限且未过期 expires 的模型 allow/deny，并要求策略、cwd、输入及附件摘要匹配。损坏条目、缺失期限、非法类型或不符合当前结构的旧条目不会被直接信任。不承诺与旧缓存键兼容。

## 保存成功却不生效，或写盘失败怎么办？

CLI 与加载端采用一致的校验限制，超限规则不得悄悄生效。检查命令完整错误与退出码，写失败应返回 exit 1，不应报告成功。不要绕过 CLI 手改规则来规避上限。

## hook schema 校验失败怎么办？

检查客户端日志与 `src/decision.js` 的标准 `hookSpecificOutput` 输出，不再使用 `AUTO_REVIEW_OUTPUT_STYLE=simple`。PreToolUse 使用 `permissionDecision/permissionDecisionReason`，PermissionRequest 使用 `decision.behavior/message`，两套字段不可混用。PreToolUse 协议异常阻断，PermissionRequest 对看不懂的输入空输出退避，进程崩溃 exit 2。客户端对 reason 的显示可能受权限合并逻辑影响，additionalContext 用于补充给主 agent，不保证每种客户端界面都显示同样文本。

## 如何验证修复？

在项目根目录执行 `npm test`，使用离线单元、场景与冒烟测试；不需真实 API key，也不要通过执行破坏性命令验收。数量与结果以当次输出为准。插件更新后 ctl.js 缓存路径可能变化，应重新定位，不能猜测旧版本路径。
