# 常见问题（0.5.1）

## GUI、审查窗口与 session 命令去哪里了？

当前版本已移除插件 GUI、自建审查对话框与插件会话白名单。不要使用旧版 `gui`、`session`、`dialog_on_ask`、`ask_to_user` 配置方式；ask 统一交客户端原生审批，会话内允许由客户端自行处理。远程端能否呈现审批由客户端决定，插件不根据不可信来源字符串猜测远程状态。

## 为什么开了插件仍然询问？

先检查 `/auto-review`、自动编辑权限模式及 hook 日志。ask 可能来自显式确认规则、provider 未配置/故障、超出 payload 预算或必要脚本内容不完整。插件关闭、工具范围外或非接管模式则由客户端流程决定是否询问。

## ask 与 deny 谁优先？

固定为 `ask > deny（风险提示）> allow`，不取决于数组顺序。ask 只在管线接管后生效；deny 规则不是立即拒绝，而是禁止捷径并携带提示送审。模型 deny 才是模型层拒绝；模型返回 ask 按 deny 处理，故障兜底 ask 则保留人工确认。

## rules test 能验证拟添加 pattern 吗？

不能。`/danger-rules test 'git status'` 测试的是已经保存的规则，不会执行这段命令，也不模拟完整审查管线。添加前审阅正则和范围，经授权保存后再 test；未命中不等于安全或自动放行。

## 为什么普通 Git 命令也没有快速放行？

快速通道不仅看命令名，还检查参数、路径和结构。危险或未知选项、包装器、重定向、命令替换或无法可靠解析的语法会退出捷径。不是所有 Git 参数安全，解析器也不是所有 shell 的完整实现。不要用宽泛 allow 消除这些检查。

## 脚本会发给谁？截断后是否仍会自动允许？

开启 inspect_scripts 后，允许附加的内容会发给 `review_provider.json` 中的专用渠道。只尝试读取 cwd 内普通文件，并检查越界、链接、敏感目录路径组件及文件类型。工具内容、附件、上下文、规则提示和格式开销共享单一总预算；必要输入缺失或脚本标记 truncated 时不能自动 allow，应转人工。默认关闭此功能，开启前确认渠道可信。

## 脱敏能保证所有秘密都不外泄吗？

不能。实现先脱敏原始字段再序列化，并保护渠道展示中的短 key，但只覆盖已识别的凭据模式。附件可能包含未识别的秘密。分享日志、截图或配置前仍须检查，不要依赖绝对“不会泄漏”的承诺。

## 审批渠道如何排查？

`provider path` 定位配置，保留 base_url、api_key、api_kind、model 四项；`provider show` 脱敏展示；`provider test` 真实联网检查。未配置、认证失败、超时或输出无效时，需要模型的请求转 ask，不回落客户端 provider。连通性测试不是 `npm test` 的一部分。

## 缓存是否固定一小时？旧缓存兼容吗？

不固定，TTL 取决于 cache_ttl_seconds，0 禁用。缓存只复用有效 schema、有限且未过期 expires 的模型 allow/deny，并要求策略、cwd、输入及附件摘要匹配。损坏条目、缺失期限、非法类型或不符合当前结构的旧条目不会被直接信任。不承诺与旧缓存键兼容。

## 保存成功却不生效，或写盘失败怎么办？

CLI 与加载端采用一致的校验限制，超限规则不得悄悄生效。检查命令完整错误与退出码，写失败应返回 exit 1，不应报告成功。不要绕过 CLI 手改规则来规避上限。

## hook schema 校验失败怎么办？

检查客户端日志与 `src/decision.js` 的标准 hookSpecificOutput 输出，不再使用 `AUTO_REVIEW_OUTPUT_STYLE=simple`。hook 协议异常阻断，进程崩溃 exit 2。客户端对 reason 的显示可能受权限合并逻辑影响，additionalContext 用于补充给主 agent，不保证每种客户端界面都显示同样文本。

## 如何验证修复？

在项目根目录执行 `npm test`，使用离线单元、场景与冒烟测试；不需真实 API key，也不要通过执行破坏性命令验收。数量与结果以当次输出为准。插件更新后 ctl.js 缓存路径可能变化，应重新定位，不能猜测旧版本路径。
