# 使用指南

## 默认裁决行为（全自动二值）

默认（`ask_to_user: false`）是**全自动二值裁决**，审批模型在场的日常操作不打扰你：

- **allow** → 命令立即执行；
- **deny** → 命令拦截，风险分析与更安全做法经 additionalContext **回传主 agent**，它会修改方案后自动重试；
- 安全子 agent 给出存疑（ask）时同样**收敛为拒绝 + 回传分析**，不弹窗。

两类情况例外，始终会找你确认：你设置的 `ask` 规则（如关机确认门槛）、审批模型不可用时的兜底转人工。

## 审查对话框（可选，`dialog_on_ask=true` 时介入）

ask 决策（你设置的确认门槛、模型存疑、模型不可用兜底）默认走客户端原生审批框；
`/auto-review set dialog_on_ask true` 后改弹插件的深色审查对话框：

- 展示完整分析（风险徽章 + 命令 + 分析/风险点/影响范围），你的点击直接决定放行/阻断。三个按钮：
  - **允许执行**：本次放行（下次同指令仍会审查）；
  - **本次会话允许**：放行且同一指令在本对话内**不再询问**（精确匹配整条指令；新增的 deny/ask 危险规则
    仍优先生效；跨会话或超 24 小时自动失效，`/auto-review session list|clear` 可查看与清空）；
  - **拒 绝**：阻断（关闭窗口均等同拒绝）。
- 键盘操作：**左右方向键**移动按钮光标（白框，初始在「拒 绝」），**回车**点击光标所在按钮，**Esc** = 拒绝。
- 对话框**不会自动消失**（关闭窗口=拒绝）；锁屏/无交互桌面弹不出时会自动回落客户端原生审批，
  绝不把"没弹框"当用户拒绝。注意它是主机本地窗口，**远程控制（手机）场景看不到**——
  检测到远程会话标记时插件会自动跳过对话框，改走客户端（手机端）审批。

## 图形配置界面

```
/auto-review gui
```

打开深色主题设置窗口（与审查对话框同风格），可视化配置：

- **开关**：启用自动审批 / 存疑转用户
- **审查范围**：Bash / Write / Edit 勾选；「脚本内容随命令送审」勾选 + 单文件字节上限
  （开启后 python/node/bash 等调用的脚本文件内容随载荷一并送审）
- **审批渠道**：在 `~/.zcode/auto-review/review_provider.json` 配置（窗口内有路径提示），
  `/auto-review provider path|show|test` 定位/查看/实测
- **危险规则**：列表展示、添加（正则即时校验）、删除、命中测试、恢复出厂
- **安全策略提示词**：「打开提示词编辑器」进入独立编辑窗口——显示当前全文、就地修改、
  恢复出厂内容；保存时校验输出契约字段（decision/risk_level/analysis/risks/scope
  缺失会警告确认），保存后立即生效（每次审查前现读文件）

点击「保存」写入配置即时生效；所有能力与命令式配置完全等价，按习惯选用。

## /auto-review —— 总控

| 用法 | 效果 |
|------|------|
| `/auto-review` | 查看状态：开关、审查工具、审批渠道、规则条数、提示词是否自定义 |
| `/auto-review on` / `off` | 开启 / 关闭自动审批 |
| `/auto-review set <key> <value>` | 修改配置 |

常用配置项：

```
/auto-review set review_tools '["Bash","Write"]'  # 扩大审查范围到文件写入
/auto-review set cache_ttl_seconds 7200     # 延长缓存有效期
/auto-review set inspect_scripts true       # 开启脚本内容随命令送审（默认关）
/auto-review set script_max_bytes 32000     # 脚本送审单文件读取上限（默认 16000）
/auto-review set ask_to_user true           # 模型存疑时转你裁决（默认收敛为拒绝）
/auto-review set dialog_on_ask true         # ask 决策弹插件审查对话框（默认客户端原生框）
```

审批渠道与模型**不在 set 管理范围**：只认 `review_provider.json`（`/auto-review provider path` 定位）。

## /danger-rules —— 危险规则（本地路由层）

规则是本地正则，扫描优先级固定：deny/ask 压过 allow（宽泛 allow 排前面也遮不住）。三种动作：

- `deny`：**不再直接拦截**——命中后提炼风险提示送审，由审批模型结合完整命令裁决（模型的 deny 才是真正的拒绝）
- `ask`：转用户确认（命中即弹审批框，你点允许才执行——用户显式配置的确认门槛，无论何种模式生效；典型用途：关机/重启这类"需要我点头"的操作）
- `allow`：白名单直接放行（跳过 LLM，用于高频安全命令提速，仅对单段命令生效）

```
/danger-rules                                            # 查看全部规则
/danger-rules test 'git push origin main --force'        # 先测一条规则是否会命中
/danger-rules add deny 'drop\s+database\b' '删库不可恢复'  # 加规则（正则用单引号包裹）
/danger-rules add allow '^git\s+status\b' 'git status 白名单'
/danger-rules remove 3                                   # 按序号删规则
```

也可以直接说人话，例如"帮我加一条规则：所有 docker 命令都要送审"——主 agent 会转写正则、
先 test 验证再落盘。出厂只内置 6 条高危规则：5 条不可逆提示（rm -rf 根目录/家目录/盘符、
格式化磁盘、dd 写块设备、fork 炸弹、chmod -R 777 根目录——命中后作为强风险提示送审）
+ 1 条关机确认门槛（覆盖裸命令/shutdown.exe/cmd/PowerShell/wmic 包装形态，用户主动要求
关机时点允许即可）；sudo、强推、注册表等常规风险操作交给安全子 agent 裁量，不预设拦截。

## /security-prompt —— 审查策略调优

```
/security-prompt                # 查看当前提示词全文
/security-prompt edit 审查更严格一些，任何数据外传都拒绝   # 按自然语言要求改写
/security-prompt reset          # 恢复出厂默认
```

图形化方式：`/auto-review gui` → 「打开提示词编辑器」，全文显示、就地编辑、
恢复出厂、保存即生效（保存时自动校验输出契约字段）。

改写立即生效（每次审查前现读文件）。**输出契约段的 JSON 字段名不可改**，
否则所有审查会解析失败兜底转人工审批（命令与 GUI 编辑器都会自动保护该段）。

## 审查日志

`~/.zcode/auto-review/review.log` 每行一条决策，标注来源层：

```
[2026-08-29T08:00:01Z][INFO][rule]  hint Bash: rm -rf / (危险规则提示送审)
[2026-08-29T08:00:03Z][INFO][fast]  allow Bash: git status（快速通道示例）
[2026-08-29T08:00:05Z][INFO][llm]   allow risk=low 1.5s（专用审批渠道）
[2026-09-05T08:00:07Z][INFO][script] 脚本送审 1 个文件: deploy.py   # 开启脚本送审后
[2026-08-29T08:00:09Z][WARN][fallback] 审查不可用: HTTP 401: ...
```

排查插件行为先看这里；hook 层面的执行记录（触发/超时/阻断）另见 ZCode 日志。

## 推荐搭配

1. 权限模式：**自动编辑模式**（自动审批的设计基座）
2. 低风险命令快速通道已内置 25 类（零延迟）；高频安全命令再加 `allow` 白名单
3. 高风险操作加 `deny` 规则（提炼风险提示送审，由审批模型结合完整命令裁决）；需要你亲自拍板的操作加 `ask` 规则（恒转你确认）
4. 审批渠道配 flash 级快模型（review_provider.json 里改）
