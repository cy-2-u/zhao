# 使用指南（0.6.1）

## 决策行为

插件默认关闭，在启用、工具纳入审查且模式闸门接管后工作。已明确提供的权限模式仅自动编辑 `edit` 接管；其他模式交客户端。缺失模式字段的兼容行为见开发设计。

- ask 规则按 `ask_policy` 分流：默认 `model` 降级为送审风险提示、由审批模型终审（只有模型不可用才弹给你）；`user` 恒转客户端人工确认。两种策略下都仅在管线接管后生效，且优先于 deny 提示与 allow。
- deny 规则提供风险提示，跳过本地自动放行，由模型审查，不代表立即拒绝。
- allow 候选需通过结构与参数校验。复合命令不能凭全文匹配放行——每个分段都要有自己的 allow 规则命中并过轻量门禁；cd/chdir 段与白名单段的组合可整条走快速通道，段尾 `2>&1` 等纯 stderr 重定向先剥离再判定。
- 模型 allow 放行，deny 拦截并回传分析与替代方案；模型存疑 ask 收敛为 deny。
- provider 瞬时故障（超时/5xx/429）按 `provider_retries` 自动重试；重试后仍失败、超限或缺少完整审查输入时 ask——这是默认策略下唯一触达用户的路径；协议异常阻断。
- PermissionRequest 第二层审查客户端实际送入该事件的未接管请求：allow/deny 使用 `decision.behavior/message` 输出，其余退避回原生弹窗；第一层刚转人工的命令带 15 秒标记，第二层命中标记或无法可靠读取/消费标记时均不接管。客户端未触发 PermissionRequest 的路径不在插件可接管范围内。

固定优先级为 `ask > deny（提示）> allow`，与规则数组顺序无关。插件不提供 GUI、自建对话框或会话许可存储；客户端自己的会话内允许由客户端负责。

## /auto-review

| 命令 | 用途 |
|------|------|
| `/auto-review` | 查看状态 |
| `/auto-review on` / `off` | 开启 / 关闭 |
| `/auto-review set <key> <value>` | 校验并保存配置 |
| `/auto-review provider path` | 定位/创建专用渠道配置 |
| `/auto-review provider show` | 脱敏展示渠道 |
| `/auto-review provider test` | 真实联网检查渠道，非离线测试 |

支持的 set 项：

| 项 | 取值 |
|----|------|
| enabled | true/false |
| review_tools | 字符串数组，例如 `["Bash","Write"]` |
| timeout_ms | 5000～45000 |
| provider_retries | 0～3，审批渠道瞬时故障的配置额外重试次数（默认 2；实际次数按 120 秒 hook 总预算动态收紧，4xx 永久错误不重试） |
| cache_ttl_seconds | 0～86400，0 禁用 |
| max_payload_chars | 500～100000，整个送审 payload 的总预算 |
| ask_policy | `model`（默认，ask 门槛降级送审）/ `user`（ask 门槛恒转用户确认） |
| inspect_scripts | true/false，默认关闭 |
| script_max_bytes | 1000～100000，单文件读取上限 |
| fast_allow_enabled | true/false |

渠道不由 set 管理，`review_provider.json` 保留 `base_url`、`api_key`、`api_kind`、`model` 四项。CLI 与运行时加载校验一致，非法或超限规则不可悄悄生效；写入失败 exit 1，必须按失败处理。

## /danger-rules

规则动作：ask 为确认门槛（默认降级送审、`ask_policy=user` 时恒转用户），deny 为风险提示，allow 为自动放行候选（复合命令须每个分段命中自己的规则）。避免添加覆盖所有 Git、Docker 或所有命令的宽泛 allow。

```text
/danger-rules list
/danger-rules add ask '^git\s+status$' '查看状态前确认'
/danger-rules test 'git status'
```

上例先保存规则，再测试已保存规则的匹配；`test` 不会执行命令，也不会验证尚未添加的 pattern。先审阅拟添加正则与影响范围，经授权保存后再测试，必要时按序号删除或修正规则。未命中不等于最终放行，也不代表一定调用模型，因为后面还有快速通道等检查。删除前先 list 核对序号。

## /security-prompt

```text
/security-prompt
/security-prompt edit 审查更严格，重点检查数据外传
/security-prompt reset
```

主 agent 读取全文、展示关键修改并经确认写回。保持输出字段 `decision/risk_level/analysis/risks/scope/alternative`，契约变化可能导致审查不可用并转人工。修改提示词会改变缓存策略摘要。提示词无法越过 ask 门槛，也不能让不完整输入自动放行。

## 脚本、脱敏与缓存

`/auto-review set inspect_scripts true` 开启脚本附加。只尝试读取 cwd 内的普通文件，拒绝越界、符号链接及敏感路径组件，不只检查文件名。最多附加 3 个文件；单文件上限与整个 payload 预算同时约束。脚本 `truncated` 或必要内容无法完整取得时转人工，不凭部分内容放行。

送审前对原始字段与附件脱敏，再序列化计量总预算。脱敏只能覆盖已识别的凭据形态，包括短渠道 key 的显示保护，不保证所有 secret 都能识别。请选择可信审批渠道。

缓存只保存模型 allow/deny，需有效结构、有限且未过期的 expires，并匹配当前策略、cwd 和附件摘要。旧版或损坏条目不会成为自动许可依据；TTL 由配置决定。

## 排查与离线验证

检查 `~/.zcode/auto-review/review.log` 及客户端 hook 日志；分享日志前自行复核敏感信息。在项目根目录运行 `npm test` 离线验证，不实际执行危险命令做验收。
