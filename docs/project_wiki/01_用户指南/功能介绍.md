# 功能介绍（0.8.2）

## 自动审批与人工边界

auto-review 用客户端实际触发的 PreToolUse 与 PermissionRequest 两层 hook 实现全自动审批（模拟 Codex 全自动模式）：除 `plan`（只读规划边界）与完全访问（yolo，客户端原生全放行）外的所有权限模式均自动接管。规则层只有 deny/allow 两种动作，优先级为 `deny（提示送审）> allow`：deny 作为风险线索交模型分析（模型 deny 才是真正的拒绝），allow 仍需保守的结构与参数校验；规则层不存在直接转人工的确认门槛。人工审批是唯一兜底，且只由审批模型不可用触发——载荷超限截断、附件不完整等情形照常送模型裁决；客户端未触发相应 hook 的路径由客户端自身流程决定。

| 能力 | 说明 |
|------|------|
| 本地快速通道 | 有限命令及参数组合不调用模型；网页搜索/抓取等只读工具直接放行；安全组合命令（cd 段 + 白名单段、`2>&1` 尾缀）逐段判定后整条放行；不承诺所有 Git 参数安全，不按规则数量衡量覆盖率 |
| 模型审查 | 专用 provider 返回 allow/deny；deny 分析与替代做法回传主 agent；瞬时故障按 `provider_retries` 配置重试，实际次数受 120 秒 hook 总预算动态收紧 |
| 失败兜底 | 仅 provider 故障（重试后）时 ask——这是唯一触达用户的路径；协议异常阻断 |
| 客户端第二层 | hooks.json 对本层不设 matcher，客户端任何工具的弹窗请求都强制送审：子智能体创建（Agent/Task，任务文本随载荷送审）、未经过 PreToolUse 的请求与名单外工具（如默认配置下的 Write/Edit）、MCP/扩展工具；仅输入读不懂、无任务内容的子代理请求、plan 模式、第一层刚裁定人工或模型不可用时退避回原生弹窗。客户端是否触发该事件取决于实现，需实机验证 |
| 脚本附加 | 默认关闭，仅尝试读取 cwd 内安全边界内的普通文件；不完整附件以附注随载荷送模型裁决，附件摘要参与缓存键 |
| 凭据保护 | 原始字段先脱敏再序列化，附件与工具共享总 payload 预算；渠道短 key 也保护 |
| 策略缓存 | 结构与 expires 严格校验；绑定策略、工具输入、cwd 与附件摘要 |
| 配置控制 | 三个斜杠命令通过 CLI 操作；加载与保存校验一致，写失败 exit 1 |

## 安全设计不是完备保证

- 模型不接收对话历史，可减小上下文污染，但工具描述与附件仍可能携带提示注入，不能保证完全免疫。
- 命令解析器只支持有限语法，未知 shell 形式或危险参数不走快速通道；复合命令不能通过匹配全文 allow 绕过逐段检查——每个分段都需命中自己的 allow 规则并过轻量门禁。
- 敏感附件检查覆盖路径组件、目录边界与链接，不仅检查文件名；不完整附件的结论落在自己的缓存键下，完整读取的旧 allow 不可能为它背书。
- 脱敏覆盖常见凭据模式，不保证识别所有 secret，不能替代数据最小化及可信渠道选择。
- provider 不可用时，需要模型的请求 ask；这不意味着关闭独立通过保守校验的本地快速通道。
- 规则只在管线接管后生效；命中规则的去向要么白名单放行（allow）、要么模型重点审查（deny 提示），都不会直接弹窗。
- PermissionRequest 层不设 matcher（覆盖客户端实际送入该事件的任何工具请求，含子智能体创建）；脚本级 allow/deny 协议已验证，但客户端是否把某类请求送入该事件取决于实现。客户端未触发或拒绝决策输出时，效果安全退化为原生弹窗。
- 第一层转人工的 pending 标记命中时第二层退避（防回环，也省一轮注定失败的重试）；标记读取不可靠时第二层照常送审——模型在场即自动决策，不在场自然兜底转人工。

## 当前交互

只使用客户端原生审批框，不提供插件 GUI、自建审查窗口或插件会话白名单。模型存疑 ask 收敛为 deny；故障兜底 ask 不被收敛、直达用户。hook 使用标准 `hookSpecificOutput` 协议，预算 2 分钟。

Node.js ≥ 18，零第三方依赖；在项目根目录以 `npm test` 离线验证，不需要真实危险命令验收。
