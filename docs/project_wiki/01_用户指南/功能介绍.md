# 功能介绍（0.6.1）

## 自动审批与人工边界

auto-review 用客户端实际触发的 PreToolUse 与 PermissionRequest 两层 hook 减少重复审批。它不是沙箱，也不新增客户端权限模式。规则优先级为 `ask > deny（提示送审）> allow`：ask 门槛默认按 `ask_policy=model` 降级为送审提示、由审批模型终审（`user` 策略恢复恒转用户裁决），deny 作为风险线索交模型分析，allow 仍需保守的结构与参数校验。审批模型不可用、输入无法可靠判定、载荷超限或 pending 状态不可可靠读取时才默认转人工；客户端未触发相应 hook 的路径由客户端自身流程决定。

| 能力 | 说明 |
|------|------|
| 本地快速通道 | 有限命令及参数组合不调用模型；安全组合命令（cd 段 + 白名单段、`2>&1` 尾缀）逐段判定后整条放行；不承诺所有 Git 参数安全，不按规则数量衡量覆盖率 |
| 模型审查 | 专用 provider 返回 allow/deny；deny 分析与替代做法回传主 agent；瞬时故障按 `provider_retries` 配置重试，实际次数受 120 秒 hook 总预算动态收紧 |
| 失败兜底 | provider 故障（重试后）、输入超限或缺少完整审查内容时 ask——这是默认策略下唯一触达用户的路径；协议异常阻断 |
| 客户端第二层 | 客户端实际触发 PermissionRequest 时，未经过 PreToolUse 的请求可运行同一审查管线；本层任何看不懂的形态退避回原生弹窗。真实内置子智能体是否进入该事件取决于客户端，需实机验证 |
| 脚本附加 | 默认关闭，仅尝试读取 cwd 内安全边界内的普通文件；截断内容不可取得自动 allow |
| 凭据保护 | 原始字段先脱敏再序列化，附件与工具共享总 payload 预算；渠道短 key 也保护 |
| 策略缓存 | 结构与 expires 严格校验；绑定策略（含 ask_policy）、工具输入、cwd 与附件摘要 |
| 配置控制 | 三个斜杠命令通过 CLI 操作；加载与保存校验一致，写失败 exit 1 |

## 安全设计不是完备保证

- 模型不接收对话历史，可减小上下文污染，但工具描述与附件仍可能携带提示注入，不能保证完全免疫。
- 命令解析器只支持有限语法，未知 shell 形式或危险参数不走快速通道；复合命令不能通过匹配全文 allow 绕过逐段检查——每个分段都需命中自己的 allow 规则并过轻量门禁。
- 敏感附件检查覆盖路径组件、目录边界与链接，不仅检查文件名；无法取得完整必要内容时转人工。
- 脱敏覆盖常见凭据模式，不保证识别所有 secret，不能替代数据最小化及可信渠道选择。
- provider 不可用时，需要模型的请求 ask；这不意味着关闭独立通过保守校验的本地快速通道。
- ask 规则只在管线接管后生效，不是所有客户端权限模式下都运行的全局策略；`model` 策略下门槛去向是模型重点审查，`user` 策略下才是弹窗。
- PermissionRequest 层只覆盖客户端实际送入该事件的请求；脚本级 allow/deny 协议已验证，但不能据此宣称每种客户端内置子智能体都继承父级 hook。客户端未触发或拒绝决策输出时，效果安全退化为原生弹窗。
- 第一层转人工的 pending 标记如果损坏、锁状态不明或无法可靠消费，第二层直接退避到原生弹窗，不把故障当成明确未命中。

## 当前交互

只使用客户端原生审批框，不提供插件 GUI、自建审查窗口或插件会话白名单。模型存疑 ask 收敛为 deny；`user` 策略的规则 ask 与故障 ask 不被收敛、直达用户。hook 使用标准 `hookSpecificOutput` 协议，预算 2 分钟。

Node.js ≥ 18，零第三方依赖；在项目根目录以 `npm test` 离线验证，不需要真实危险命令验收。
