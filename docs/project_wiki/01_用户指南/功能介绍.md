# 功能介绍（0.5.1）

## 自动审批与人工边界

auto-review 用自动编辑模式下的 PreToolUse hook 减少重复审批。它不是沙箱，也不新增客户端权限模式。规则优先级为 `ask > deny（提示送审）> allow`：ask 由用户裁决，deny 作为风险线索交模型分析，allow 仍需保守的结构与参数校验。

| 能力 | 说明 |
|------|------|
| 本地快速通道 | 有限命令及参数组合不调用模型；不承诺所有 Git 参数安全，不按规则数量衡量覆盖率 |
| 模型审查 | 专用 provider 返回 allow/deny；deny 分析与替代做法回传主 agent |
| 失败兜底 | provider 故障、输入超限或缺少完整审查内容时 ask；协议异常阻断 |
| 脚本附加 | 默认关闭，仅尝试读取 cwd 内安全边界内的普通文件；截断内容不可取得自动 allow |
| 凭据保护 | 原始字段先脱敏再序列化，附件与工具共享总 payload 预算；渠道短 key 也保护 |
| 策略缓存 | 结构与 expires 严格校验；绑定策略、工具输入、cwd 与附件摘要 |
| 配置控制 | 三个斜杠命令通过 CLI 操作；加载与保存校验一致，写失败 exit 1 |

## 安全设计不是完备保证

- 模型不接收对话历史，可减小上下文污染，但工具描述与附件仍可能携带提示注入，不能保证完全免疫。
- 命令解析器只支持有限语法，未知 shell 形式或危险参数不走快速通道；复合命令不能通过匹配全文 allow 绕过逐段检查。
- 敏感附件检查覆盖路径组件、目录边界与链接，不仅检查文件名；无法取得完整必要内容时转人工。
- 脱敏覆盖常见凭据模式，不保证识别所有 secret，不能替代数据最小化及可信渠道选择。
- provider 不可用时，需要模型的请求 ask；这不意味着关闭独立通过保守校验的本地快速通道。
- ask 规则只在管线接管后生效，不是所有客户端权限模式下都运行的全局策略。

## 当前交互

只使用客户端原生审批框，不提供插件 GUI、自建审查窗口或插件会话白名单。模型存疑 ask 收敛为 deny；规则 ask 与故障 ask 不被收敛。hook 使用标准 `hookSpecificOutput` 协议，预算 2 分钟。

Node.js ≥ 18，零第三方依赖；在项目根目录以 `npm test` 离线验证，不需要真实危险命令验收。
