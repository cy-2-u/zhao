# 代码地图（0.8.8）

## 模块职责

| 文件 | 主要入口/职责 |
|------|---------------|
| `src/common.js` | 数据目录、路径常量（含 pending_asks.json）、日志、JSON 读取、原子写与文件锁；两层 hook 共享的 stdin 读取/JSON 形态判定/调试日志 |
| `src/shell_lex.js` | 命令词法层：顶层分割（转义态感知）、token 切分、脚本路径识别、统一 cd 段判定（fast/resolve 两模式）、共享敏感文件模式 |
| `src/tool_text.js` | 工具名归一化、plan/完全访问模式闸门、各工具"送审文本"提炼（含休眠的 Agent/Task 识别） |
| `src/verdict.js` | 模型输出合同：JSON 对象提取、parseVerdict 字段/长度/冲突校验、reason 拼装（ctl.js 独立复用，不拉入决策引擎） |
| `src/fast_allow.js` | 快速通道：stderr 剥离、跨 shell 保守文法、按命令参数白名单、白名单匹配（cd/包装器/解释器不参与） |
| `src/script_attach.js` | 脚本附件：引用解析（cwd 跟随）、安全读取（symlink/越界/敏感文件拒绝、句柄内 fstat 复核）、动态执行命令判定 |
| `src/decision_cache.js` | 决策缓存：策略盐（版本/设置/规则/白名单/提示词/渠道）、缓存键、锁内读改写，只承载 allow/deny |
| `src/pending_marks.js` | pending 转人工标记：键计算、写/一次性消费、hit/miss/error 三态合同 |
| `src/settings.js` | `loadSettings`（含 provider_retries 校验钳制）、规则读取/校验/编译、提示词与快速通道加载、`loadPolicySnapshot`（同请求策略只读一次）；CLI 与加载端共享规则校验约束 |
| `src/provider.js` | `resolveProvider`、`callLlm`：只读专用渠道，OpenAI/Anthropic 请求、共享绝对 deadline、按 `provider_retries` 重试（4xx 不重试）、json_object 能力按渠道+模型隔离 |
| `src/reviewer.js` | 管线编排（`reviewToolUse`/`force_review`）：模式边界 → 只读工具白名单 → 名单过滤 → 规则层 → 复合逐段 → 快速通道 → 附件 → 缓存 → 模型 → 兜底；兼容门面再导出各模块符号 |
| `src/decision.js` | `emitDecision`（PreToolUse）/ `emitPermissionDecision` + `emitPass`（PermissionRequest）/ `emitCrash` 阻断退出 |
| `src/hook_main.js` | PreToolUse 入口：共享输入读取、调用 reviewer、ask 时写 pending 标记、输出决策 |
| `src/hook_permission.js` | PermissionRequest 入口：本层不设 matcher，客户端实际送入该事件的弹窗请求强制送审（名单外工具与 MCP/扩展工具；子智能体请求当前客户端不投递，Agent 识别为休眠能力），pending 命中/不可靠退避，allow/deny 输出、其余空输出退避 |
| `src/ctl.js` | init/status/set（含 provider_retries）、rules、prompt、provider；校验与写入错误 exit 1 |

## reviewer 定位

- 规则：`matchDangerRules` / `matchCompoundRules`。固定 `deny（提示）> allow`，全文 allow 不能直接覆盖复合命令；ask 已不是规则动作（旧条目归一为 deny 送审）；deny 提示不得被本地捷径遮蔽。
- 解析：`splitTopLevelCommands`（fd 复制后缀 `2>&1` 不切分）、`stripStderrRedirect`、`tokenizeSegment`。有限 shell 语法辅助解析，不保证解析任意 shell；自动 allow 必须另行保守校验结构和参数。
- 快速通道：`matchFastAllow` / `matchFastSegment` / `isFastCdSegment`。`cd`/`chdir` 段不参与快速通道（命中即整条降级模型）；白名单段过严格双门禁，全部段可放行才整条 0 LLM 放行。
- 用户 allow 门禁：`userAllowSegmentSafe` / `unquotedRedirectOrMalformed`。信任边界是用户正则，只兜底命令替换、反引号、引号外重定向、未闭合引号、`\&` 类跨 shell 歧义与 `%VAR%` 展开。
- 脚本：`extractScriptRefs` / `collectScriptAttachments`。cwd 边界、普通文件、链接、敏感路径组件、数量及读取限制；不完整附件以附注随载荷送模型裁决，附件摘要参与缓存键。
- 载荷：`buildReviewPayload`。先脱敏原始字段再序列化，工具、附件、上下文及规则提示共用一个 max_payload_chars，超预算截断加显式标记（要求模型无法判断时必须 deny）。
- 缓存：`computeCacheKey` / `reviewCacheKey` / `readCachedDecision` / `writeCachedDecision`。策略摘要、cwd、输入、附件摘要参与键；严格检查条目结构、有限 expires 与到期状态，不兼容性信任旧条目。
- 标记：`pendingAskKeyForInput` / `writePendingAskMarker` / `takePendingAskMarkerState`。第一层 ask 写 15s 短时效标记（键含工具名、完整输入、规则文本、cwd 与请求身份），第二层一次性消费；命中退避（人工路径不被翻转），miss 照常送审，error（损坏/读取/消费失败）同样退避——无法证明第一层是否已交人工时不继续自动裁决。
- 模型：`parseVerdict` / `formatVerdictReason`。模型 allow/deny，模型 ask 收敛 deny；仅模型链路故障 ask；ask/deny 通过 additionalContext 向主 agent 补充原因。

函数的具体参数以源码为准，安全修复期间不把内部签名当稳定公共 API。

## 配置与规则

`settings.js` 的 `validateDangerRule` 被 CLI 与加载端复用；规则数量、pattern 与描述长度均有上限。危险规则整表超限不能简单截去尾部，应整表按风险提示送审；快速通道超限应停用捷径。CLI 拒绝不合法写入，不报告“成功但运行时忽略”。

## 接口与验证

hook 输出为 `hookSpecificOutput`。PreToolUse 使用 `hookEventName`、`permissionDecision`、`permissionDecisionReason` 和可选的 `additionalContext`；PermissionRequest 使用 `hookEventName` 与 `decision.behavior/message`。pass 空输出，崩溃 exit 2；PermissionRequest 只有 allow/deny 有输出，其余空输出退避。不再提供 simple 输出切换、dialog/gui 模块或插件 session 命令。

`hooks/hooks.json` 在 PreToolUse 上按名单 matcher 注册 Bash/Write/Edit/ApplyPatch/WebSearch/WebFetch/mcp__web_reader__webReader，PermissionRequest 不设 matcher（匹配所有工具，客户端任何弹窗请求都进入第二层）；timeoutMs 均为 120000。运行 `npm test` 执行离线验证；不要用实际危险命令验收。
