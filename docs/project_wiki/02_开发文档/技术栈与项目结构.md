# 技术栈与项目结构

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 运行时 | Node.js ≥ 18 | 仅内置模块（fs/path/crypto/http/https），零第三方依赖 |
| 插件接口 | ZCode 插件体系 | 根目录 `marketplace.json`（市场清单）+ `.zcode-plugin/plugin.json`（清单：hooks + commands） |
| hook 协议 | PreToolUse | stdin 收 hook JSON，stdout 输出 `hookSpecificOutput.permissionDecision`；总预算 1 小时（支撑对话框持久等待） |
| LLM 协议 | Anthropic Messages / OpenAI Chat Completions | 按专用审批渠道（review_provider.json）的 api_kind 二选一；anthropic 显式关闭 thinking（GLM 混合推理模型默认长思考会吃掉 token 额度导致正文为空）；node:http 直连 + connection: close（避免 undici 长连接在进程退出时触发 libuv 崩溃） |
| GUI | PowerShell WinForms | 审查对话框 + 图形配置界面；Win11 DWM 圆角/深色标题栏、自绘勾选框与下拉、OwnerDraw 列表 |
| 测试 | node:test + 子进程冒烟 + PS 语法校验 | 无测试框架依赖 |

## 目录结构

```
（仓库根 = 插件根）
├── marketplace.json              # 市场清单：客户端本地市场源入口（探测根目录此文件）
├── .zcode-plugin/plugin.json     # 插件清单（commands + hooks）
├── hooks/hooks.json              # PreToolUse 注册（matcher Bash|Write|Edit|ApplyPatch，process 型，timeoutMs 3600000）
├── commands/                     # 三个斜杠命令（指导主 agent 调 ctl.js）
│   ├── auto-review.md            # 总控：status / gui / on / off / set / provider / session
│   ├── danger-rules.md           # 危险规则 CRUD + test
│   └── security-prompt.md        # 提示词 show / edit / reset
├── src/                          # 核心源码（8 个模块，全部 ES Module）
│   ├── common.js                 # 路径常量/统一日志（轮转）/原子写/防御式 JSON 读
│   ├── settings.js               # 配置与规则加载（回落出厂默认 + 类型钳制 + 正则容错编译）
│   ├── provider.js               # 专用审批渠道解析（review_provider.json，唯一 LLM 来源）+ 双协议 LLM 调用
│   ├── reviewer.js               # 决策管线：开关→工具过滤→非自动模式探测→规则层→复合逐段→快速通道→会话白名单→缓存→LLM→兜底
│   ├── decision.js               # hook 输出协议封装（claude/simple 风格，唯一客户端耦合点）
│   ├── dialog.js                 # 审查对话框（深色主题/风险徽章/命令卡片/持久等待）+ reason 解析
│   ├── gui.js                    # 图形配置界面（扁平分区/自绘组件/规则管理/保存）
│   └── ctl.js                    # 控制 CLI：init/status/set/rules/prompt/provider/session/gui
├── config/                       # 出厂默认（只读回落源）
│   ├── default_settings.json     # 10 键默认值（enabled/ask_to_user/dialog_on_ask 默认 false，fast_allow_enabled 默认 true）
│   ├── default_danger_rules.json # 6 条高危规则（5 条 deny=送审风险提示 + 1 条 ask=关机确认门槛）
│   ├── default_fast_allow.json   # 25 条低风险命令快速通道白名单
│   └── default_security_prompt.md# 安全子 agent 系统提示词（规则提示只是线索；双值契约，deny 必给 alternative）
├── scripts/                      # 测试与维护脚本
│   ├── unit_tests.test.js        # 单元测试（32 项）
│   ├── scenario_tests.test.js    # 场景固定测试（22 场景 + 假 LLM 服务器，离线）
│   ├── smoke_test.js             # 端到端冒烟（16 项断言组，不触网）
│   ├── llm_smoke.js              # 真实 LLM 链路冒烟（复制真实 review_provider.json；未配置自动跳过）
│   ├── validate_ps.js            # GUI 的 PowerShell 脚本语法静态校验
│   ├── probe_window.ps1          # 窗口可见性探测器（按标题枚举 hwnd）
│   └── sanitize_docs.mjs         # 文档隐私清洗（一次性维护）
└── docs/                         # 需求、方案、wiki、日志、过程归档
```

## 运行时数据目录（不在仓库内）

`~/.zcode/auto-review/`：settings.json / review_provider.json（专用审批渠道，审批唯一
LLM 来源）/ danger_rules.json / fast_allow.json / security_prompt.md / cache.json /
session_allowlist.json / review.log。
由 hook 进程与主 agent（经 ctl.js / GUI）共同读写；测试用 `AUTO_REVIEW_DATA_DIR` 重定向隔离。

## 关键设计决策（当前生效）

- 市场清单在**根目录** `marketplace.json`（客户端只探测根目录或 `.claude-plugin/` 两处）；
- hook 预算 1 小时（配置在会话启动时绑定，改 hooks.json 需新会话生效）；
- **全自动二值裁决为默认**（ask_to_user=false）：审批模型的 ask（存疑）收敛为 deny +
  additionalContext 回传，无人工环节；ask_to_user=true 时模型存疑保持 ask 转用户裁决
  （`dialog_on_ask=true` 走插件对话框，点击映射为 allow/session/deny；默认走客户端原生审批框）；
- **规则层三态路由**（0.4.0，Codex 式审批）：allow=单段命令快速放行；ask=用户显式确认门槛
  （如出厂关机/重启规则）恒转用户裁决——模型看不到对话历史，无法替用户判断"这是不是我
  要求的"；deny 不再直接拦截——提炼 ruleHint 风险提示随载荷送审，由审批模型结合完整命令
  裁决，模型的 deny 才是真正的拒绝；固定优先级 deny/ask > allow，宽泛 allow 遮不住风险规则；
- **审批只认专用审批渠道** review_provider.json，不回落 ZCode provider 表（主 agent 渠道多为
  需客户端签名的 Coding Plan，直连必败）；渠道未配置/不可用时兜底转人工审批（ask）——
  模型不在场绝不自动许可，恢复后该命令重新进入自动审查；
- deny 决策同时输出 additionalContext（分析 + alternative 送入主 agent 上下文，供修改重试）。
