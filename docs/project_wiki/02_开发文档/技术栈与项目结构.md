# 技术栈与项目结构（0.5.1）

## 技术栈

| 层 | 技术 |
|----|------|
| 运行时 | Node.js ≥ 18，ES Modules，仅内置模块，零第三方依赖 |
| 插件 | 根目录 marketplace.json + .zcode-plugin/plugin.json |
| hook | PreToolUse，stdin JSON，stdout hookSpecificOutput，预算 120000ms（2 分钟） |
| 审批渠道 | OpenAI Chat Completions / Anthropic Messages，node:http/https |
| 测试 | node:test、隔离子进程与本地模拟服务；npm test 离线运行 |

无 PowerShell WinForms 运行时依赖，不提供插件 GUI、自建审批框或插件会话白名单。

## 运行时数据

默认 `~/.zcode/auto-review/`：settings.json、review_provider.json、danger_rules.json、fast_allow.json、security_prompt.md、cache.json、review.log。测试通过 `AUTO_REVIEW_DATA_DIR` 隔离，不应读取或改写真实用户数据。

provider 四项接口保持 `base_url`、`api_key`、`api_kind`、`model`。审批只认专用渠道；不回落客户端 provider 表。

## 关键契约

- 接管模式内规则优先级 `ask > deny（提示）> allow`，快速通道还需参数/结构校验。
- provider 故障、payload 超限或必要输入不完整 ask；协议异常阻断，崩溃 exit 2。
- 原始字段先脱敏再序列化，工具与附件共用总预算；敏感目录按路径组件检查。
- 缓存只复用有效 schema、有限且未过期 expires 的模型 allow/deny，绑定策略及输入上下文。
- CLI 与加载校验一致，写失败 exit 1；测试不硬编码通过数量。
- hook 配置是否需新会话加载由客户端决定，更新后应核实注册状态。

版本清单为 0.5.1，现有项目目录名 auto-review-0.5.0 不需重命名。
