# 模块设计：决策管线（0.7.1）

## 决策顺序与不变量

下图表达安全约束，不要求内部函数逐行按图排列；任何自动 allow 前均须满足其适用的保守校验条件。

```mermaid
flowchart TD
    A[hook 输入] --> B{协议合法?}
    B -- 否 --> D[deny 阻断]
    B -- 是 --> C{启用/plan·完全访问边界/工具范围需接管?}
    C -- 否 --> P[pass 客户端流程]
    C -- 是 --> E{全文及分段规则}
    E -- deny --> H[风险提示送审 不走捷径]
    E -- allow或未命中 --> F{结构与参数保守校验通过?}
    F -- 本地放行条件满足 --> L[allow]
    F -- 否 --> H
    H --> S[可选脚本附件 原始字段脱敏 序列化]
    S --> T{超预算?}
    T -- 是 --> T2[截断加显式标记]
    T -- 否 --> K
    T2 --> K{有效schema/expires及策略键缓存?}
    K -- 是 --> V[复用模型allow/deny]
    K -- 否 --> M[专用provider审查]
    M -- "故障（重试后）或输出无效" --> Q[ask 客户端原生审批 唯一人工路径]
    M -- allow --> L
    M -- deny或模型ask --> D
```

1. **接管边界**：关闭、plan 或完全访问（yolo）模式 pass；其余模式（default/edit 及字段缺失）全接管——全自动审批语义下人工弹窗只允许在模型不可用时出现。PermissionRequest 还受客户端是否触发该事件约束。
2. **固定优先级**：`deny（提示）> allow`，全文和复合段共同考虑；不能因宽泛 allow 提前返回。ask 已不是规则动作——旧 ask 条目归一为 deny 送审。
3. **本地 allow 保守**：正则仅为候选，结构与参数另行校验。复合全文 allow 不直接生效——每个分段须命中自己的 allow 规则并过轻量门禁（命令替换、引号外重定向、`%VAR%` 展开与 `\&` 类跨 shell 歧义形态兜底拒绝）；cd/chdir 段与白名单段的组合逐段判定后可整条快速放行；未知参数与不能可靠识别的 shell 形式不走捷径。
4. **deny 规则不是拒绝**：携带 ruleHint 交模型，模型结合完整对象裁决。命中后不得被快速通道遮蔽。
5. **模型与故障区分**：模型 allow/deny；合法模型 ask 收敛为 deny。provider 瞬时故障按 `provider_retries` 重试；重试后仍故障则 ask——唯一人工路径，不把失败当成模型拒绝或许可。载荷超限截断、附件不完整带附注照常送模型，不单独转人工。

## PermissionRequest 第二层（0.7.1）

客户端把工具调用送入 PermissionRequest 事件时，第二层以 `force_review` 强制送审——跳过 `review_tools` 名单过滤，名单外工具（如默认配置下的 Write/Edit）与子智能体请求同样由模型裁决。它只覆盖客户端实际触发该事件的路径，不能在客户端绕过 hook runner 时强行接管：

- **只对 allow/deny 输出决策**：使用 `hookSpecificOutput.hookEventName = "PermissionRequest"`，并在 `decision.behavior/message` 中输出；ask、pass、识别不了的对象、plan 模式一律空输出退避。退避方向是"交原生弹窗"而不是放行，本层故障只损失自动化。
- **防回环与裁决优先**：第一层决定转人工时以 `pending_asks.json` 写入 15 秒短时效标记（键 = 工具名 + 规则文本摘要）；第二层命中标记即退避，"模型不可用→人工"的既定路径不被翻转为自动放行，也省掉一轮注定失败的重试。标记一次性消费、过期自动清理；标记读取不可靠（error）时第二层照常送审——模型在场即自动决策，不在场由管线自然兜底 ask 退回弹窗，人工仍只与模型可用性挂钩。
- **契约不确定时安全退化**：客户端若不接受该事件名下的决策输出，或完全不触发该事件，插件无法强行接管；效果等同原生弹窗，不会放大放行范围。

## 附件、脱敏与总预算

inspect_scripts 默认关闭。开启后尝试提取已知解释器/脚本引用，不能声称覆盖任意 shell 或模块加载行为。

- 仅 cwd 内普通文件，检查目录边界、符号链接和敏感路径组件；敏感目录中的普通文件也不能因文件名无敏感词而附加。
- script_max_bytes 限制单文件读取；附件数量另有限制。
- 不完整附件（读取失败、截断）以附注随载荷送模型裁决；附件摘要（含截断标记与附注）参与缓存键，完整读取的旧 allow 不可能为不完整读取背书。
- 对工具输入原始字段与附件内容脱敏后再序列化，避免转义、嵌套字段导致常见凭据漏检。
- max_payload_chars 是单一总预算：工具内容、cwd、规则提示、附件以及序列化格式开销均计入，不能再给附件追加独立预算。
- 超预算截断保留前缀并追加显式标记（要求模型无法判断时必须 deny），照常送审；脱敏不是万能 secret 检测器，载荷仍需按不可信敏感数据处理。

## 缓存

稳定序列化工具名与输入，结合 cwd、附件摘要、危险规则/快速通道/提示词/渠道等策略摘要生成键。策略或脚本内容改变后不复用旧结论，不承诺旧键兼容。

缓存只承载模型 allow/deny，不存故障或人工授权。读取时检查 schema 与字段类型、合法决策、有限数值 expires、到期状态及适用期限。无 expires、非法类型、无效结构或过期条目不作为许可依据。TTL 由 cache_ttl_seconds 决定，0 禁用；写入使用原子写与并发保护。

缓存命中的 deny 也需向主 agent 回传分析。

## 配置与控制 CLI

CLI 添加规则和加载端复用校验约束，包括动作、正则语法、数量和长度限制。危险规则整表超限不能只截取前半段，避免遗漏尾部规则；整表按风险提示送审（模型不可用时转人工）并说明。快速通道超限停用捷径。CLI 拒绝无效/超限写入，写失败 exit 1，不宣称保存成功。provider 展示保护短 key，四项配置接口不变。

## 输出与失败分类

| 情况 | 结果 |
|------|------|
| provider 未配置、超时、HTTP 错误、输出不可解析（重试后） | ask，并说明审查不可用——唯一人工路径 |
| 载荷超限 | 截断加标记送审，不转人工 |
| 附件不完整 | 附注随载荷送审，不转人工 |
| 模型 deny / 模型存疑 ask | deny，并回传分析与替代方案 |
| 空 stdin、非法 JSON、缺工具名、非法工具输入等协议异常 | deny 阻断 |
| hook 进程崩溃 | exit 2 阻断 |
| 控制 CLI 写入失败 | exit 1 |

标准输出仅使用 hookSpecificOutput，不提供 simple 兼容开关。PreToolUse 使用 `permissionDecision/permissionDecisionReason`，PermissionRequest 使用 `decision.behavior/message`，两套字段不能混用。PreToolUse 层 ask/deny 的 additionalContext 补充给主 agent；PermissionRequest 层只有 allow/deny 有输出、其余空输出退避；最终审批 UI 由客户端负责，无插件会话白名单。

## 信任边界与验证

不接收对话历史可以减小上下文污染，但工具说明、脚本与模型输出仍是不可信数据；不承诺注入免疫、完全脱敏或完整 shell 解析。离线执行 `npm test` 验证边界回归，不实际运行危险命令验收。
