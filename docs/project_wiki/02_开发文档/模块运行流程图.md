# 模块运行流程图（0.5.1）

## 一次审查

```mermaid
sequenceDiagram
    participant M as 主 agent
    participant Z as ZCode 客户端
    participant H as hook_main
    participant R as reviewer
    participant P as provider
    participant U as 用户
    M->>Z: 工具调用
    Z->>H: PreToolUse JSON
    H->>H: 协议检查（异常阻断）
    H->>R: reviewToolUse
    R->>R: 开关、工具与模式闸门
    Note over R: 不接管则 pass；接管后 ask > deny提示 > allow
    alt 命中 ask 规则
        R-->>H: ask
    else 本地候选通过保守结构与参数校验
        R-->>H: allow
    else 需要模型审查
        R->>R: 必要附件、原始字段脱敏、序列化总预算
        alt 超限或缺完整必要输入
            R-->>H: ask
        else 输入完整且预算内
            R->>R: 缓存schema/expires与策略键检查
            alt 有效缓存
                R-->>H: 模型allow/deny结论
            else 无有效缓存
                R->>P: 专用渠道审查（完整payload）
                P-->>R: 模型结果或故障
                R->>R: 模型ask收敛deny；故障ask
                R-->>H: 决策与分析
            end
        end
    end
    H-->>Z: hookSpecificOutput
    alt ask
        Z->>U: 客户端原生审批
    else deny
        Z-->>M: 拒绝及additionalContext
    else allow
        Z-->>M: 继续工具执行
    end
```

图中省略缓存写盘等内部步骤；必要输入不完整不能通过任何自动 allow 路径。模型结论缓存不是人工授权缓存，不含插件会话许可。

## 配置路径

```mermaid
flowchart LR
    U[用户] --> C[三个斜杠命令]
    C --> A[主 agent]
    A --> CLI[ctl.js]
    CLI --> V[共享校验约束]
    V --> W[原子写]
    W -- 成功 --> D[(运行时数据目录)]
    W -- 失败 --> E[exit 1 报错]
    D --> H[hook 每次加载]
```

提示词 edit 由主 agent 读取全文、经用户确认改写；provider 四项由用户填写，不交 set 管理。没有 GUI 写入分支。

## 专用审批渠道

```mermaid
flowchart TD
    A[review_provider.json] --> B{base_url/api_key/model完整?}
    B -- 否 --> Q[ask 审查不可用]
    B -- 是 --> C[api_kind 或端点推断]
    C --> O[OpenAI Chat Completions]
    C --> N[Anthropic Messages]
    O --> R[node:http/https请求]
    N --> R
    R -- 故障重试后仍失败 --> Q
    R -- 成功 --> V[校验模型输出]
    V -- 无效 --> Q
    V -- 有效 --> D[allow/deny]
```

渠道接口保留 base_url、api_key、api_kind、model，不回落客户端 provider 表。`provider test` 真实联网；项目 `npm test` 使用本地模拟服务离线验证。hook 总预算 2 分钟，无插件对话框等待分支。
